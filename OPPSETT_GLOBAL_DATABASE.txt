OPPSETT: GLOBAL DATABASE OG ADMINISTRATORTILGANGER
==================================================

Denne filen er en praktisk oppskrift for å publisere SET18 slik at alle
besokende bruker samme backend og samme skybaserte, MySQL-kompatible database.
Filen inneholder bare veiledning; den endrer ikke programkoden.

VIKTIG FORVENTNINGSAVKLARING
---------------------------
- "Global" betyr at nettstedet naes fra internett, og at alle enheter bruker
  samme database via backend. Det betyr ikke ubegrenset lagring eller automatisk
  replikering til alle land.
- Gratisplaner har grenser, og gratis backend-tjenester kan sove nar de ikke
  brukes. De er ikke en garanti for produksjonsoppetid.
- Du trenger en konto hos en databaseleverandor, en backend-host og en
  frontend-host. Databaseleverandor er med vilje ikke valgt i denne guiden.
  Render brukes som konkret eksempel for backend og frontend.
- Databaseleverandoren ma tilby en skybasert MySQL-server, eller en tjeneste
  som er kompatibel med MySQL-protokollen, mysql2-driveren og TLS-oppsettet i
  prosjektet. PostgreSQL, SQLite og NoSQL kan ikke brukes med MYSQL_URL uten
  at backendkoden bygges om.
- Tjenestenavn og knappetekster kan endres av leverandorene. Hvis skjermbildet
  ditt avviker, folg leverandorens offisielle instruksjoner.
- Ikke legg passord, MYSQL_URL eller andre hemmeligheter i kildekode, frontend,
  denne tekstfilen eller Git.

DEL 1 - KODE OG ADMINISTRATORRETTIGHETER
----------------------------------------

Endringen i prosjektet gjor at enhver innlogget administrator kan:
- se administratorlisten fra Min side
- opprette flere administratorbrukere
- fjerne andre administratorbrukere

Hovedadministrator-kontoen (owner) kan ikke fjernes. Opprett en administrator
med e-post og et midlertidig passord. Gi opplysningene til den nye
administratoren pa en sikker mate; vedkommende bor endre passordet etter
innlogging.

For at Render skal fa denne koden:
1. Aapne VS Code og prosjektet SET18.
2. Aapne Source Control i venstre sidefelt.
3. Kontroller at prosjektendringene som skal publiseres, vises under Changes.
4. Klikk + ved Changes for a stage endringene.
5. Skriv en commit-melding, for eksempel:
   "Klargjor global database og administratorrettigheter"
6. Klikk Commit.
7. Klikk Sync Changes eller Push/Publish Branch, og bekreft hvis VS Code spor.
8. Kontroller at commit-en er pa GitHub pa grenen main.

Ikke stage en .env-fil eller passord. Den nye veiledningsfilen kan gjerne
stage-es hvis du vil at den ogsa skal vaere i GitHub; den inneholder ingen
hemmeligheter.

DEL 2 - OPPRETT DATABASE HOS EN VALGFRI LEVERANDOR
--------------------------------------------------

Databaseleverandoren er ennå ikke valgt. Derfor kan ingen liste over eksakte
knapper eller skjermbilder garantere a passe til alle leverandorer. Bruk disse
kravene nar du velger tjeneste, og folg leverandorens konsoll for de tilsvarende
handlingene.

2.1 Kontroller at tjenesten passer backend
For du oppretter databasen, kontroller leverandorens produktside eller
dokumentasjon. Tjenesten ma oppfylle ALT dette:
1. Det er en administrert database som er tilgjengelig fra internett/backend
   i skyen, ikke bare MySQL installert pa din egen datamaskin.
2. Den stotter MySQL-protokollen og vanlige MySQL-sporresprak/datatyper som
   brukes av MySQL 8-kompatible tjenester.
3. Den kan naes fra en Node.js-backend med mysql2/promise over TCP.
4. Den gir vert, port, databasenavn, brukernavn og passord.
5. Den tilbyr TLS som mysql2 kan bruke med backendens MYSQL_SSL=true-innstilling.
   Hvis leverandoren krever at du laster ned et sertifikat og sender en egen
   sertifikatfil eller en spesiell driverinnstilling, ma dette bekreftes forst:
   backend er na konfigurert med MYSQL_SSL=true og tilpasset CA-validering er
   ikke konfigurert som egen miljovariabel.
6. Den lar backendens hostingtjeneste na databasen, enten via privat nettverk
   eller via et offentlig endepunkt med IP-tilgangsregler.
7. Brukeren kan opprette og lese/skrive tabeller, eller tjenestens administrator
   kan opprette nodvendige tabeller for deg.

En tjeneste som bare tilbyr PostgreSQL, SQLite eller NoSQL passer IKKE uten
endringer i applikasjonskoden. "MySQL-compatible" bor bekreftes med
leverandoren, ikke antas ut fra markedsforing.

2.2 Opprett database/klynge
Knappene varierer mellom leverandorer, men prosessen er vanligvis:
1. Opprett konto hos databaseleverandoren og logg inn i kontrollpanelet.
2. Velg handlingen som tilsvarer Create database, Create cluster eller New
   database.
3. Velg MySQL (eller MySQL-compatible) som databaseengine/protokoll. Ikke velg
   PostgreSQL eller NoSQL.
4. Velg en region naer backend-hostens region. Hvis backendregion ikke er
   bestemt ennå, velg en region naer de fleste brukerne.
5. Velg plan/storrelse. Les pris, kvoter, dvaleregler, backup, oppetid og
   hva som skjer nar kvoten overskrides. Ikke legg inn ekte medlemsdata i en
   proveinstans for du har sjekket tilgangskontroll og sikkerhetskopi.
6. Opprett database/cluster og vent til status er Ready/Available.
7. Hvis leverandoren ber deg opprette et databasenavn separat, opprett det og
   noter det nøyaktig.

2.3 Opprett databasebruker og noter tilkoblingen
1. Aapne databaseens Connect/Connection/Networking-side.
2. Opprett en separat applikasjonsbruker hvis leverandoren anbefaler det.
   Gi bare nodvendige rettigheter til applikasjonsdatabasen: CREATE ved
   forste oppstart og SELECT/INSERT/UPDATE/DELETE/CREATE/ALTER ved vanlig
   drift, eller folg leverandorens rollemodell. Ikke bruk personlig
   hovedkonto/root-bruker hvis det kan unngas.
3. Opprett et langt, unikt passord. Hvis det vises bare én gang, lagre det i
   passordbehandler med en gang.
4. Fra Connect/Connection-instruksjonene noter:
   - Host/hostname
   - Port
   - Database/schema name
   - Username (kopier eventuelt prefiks nøyaktig)
   - Password
   - Om TLS er obligatorisk
   - Om sertifikatfil eller ekstra TLS-innstilling kreves
   - Krav til IP-allowlist, nettverk eller privat tilkobling
5. Lag MYSQL_URL i dette formatet, men IKKE skriv den inn i denne filen:

   mysql://BRUKERNAVN:PASSORD@HOST:PORT/DATABASENAVN

   URL-kod spesialtegn i brukernavn/passord (for eksempel @, :, /, #, ? eller
   %). Bruk verdiene som leverandoren gir; ikke anta at porten er 3306.
6. Hvis leverandoren krever TLS som kan brukes med denne backenden, sett
   MYSQL_SSL=true pa backend-tjenesten i del 3. Ikke send databasepassordet
   til frontend eller legg det i Git.

2.4 Planlegg nettverkstilgang sikkert
Ikke la databasen sta apen for alle IP-adresser hvis leverandoren tilbyr
IP-allowlist eller private nettverk.
1. Finn ut om backend-host og database kan kobles sammen over privat nettverk.
   Hvis ja, bruk den private tilkoblingen og folg begge leverandorenes
   konfigurasjon.
2. Hvis offentlig endepunkt og IP-allowlist er nodvendig, opprett backend-
   tjenesten i del 3 forst. Finn deretter backendens utgaende IP-adresser i
   hostingkontrollpanelet.
3. Legg backendens egress-IP-er/intervaller inn i databaseleverandorens
   Authorized networks/Firewall/IP allowlist. Legg aldri inn IP-en til
   utviklings-PC-en som erstatning for backendens IP.
4. Hvis backend-host ikke tilbyr faste/oppgitte utgaende IP-er, undersok en
   leverandorstottet privat forbindelse eller fast egress-IP. Ikke apne
   databasen for alle som en snarvei.
5. Lagre reglene og test tilkoblingen fra backendens hostingtjeneste.

DEL 3 - PUBLISER BACKEND OG FRONTEND PA RENDER
----------------------------------------------

Render-tjenestene ma hente koden fra GitHub. Koble til GitHub-kontoen og gi
Render tilgang til repoet alannala911/SET18 nar du blir bedt om det. Hvis du
velger en annen backend-host, bruk dens tilsvarende funksjon for a koble repo,
velge prosjektmappe og sette build/start-kommandoer.

3.1 Opprett frontend (for a fa dens offentlige adresse)
Frontendens adresse trengs for backendens CORS_ORIGINS.

1. Logg inn pa https://dashboard.render.com/.
2. Klikk + New oppe til hoyre og velg Static Site.
3. Velg GitHub-repoet alannala911/SET18 og klikk Connect.
4. Fyll ut:
   Branch: main
   Root Directory: frontend
   Build Command: npm install && npm run build
   Publish Directory: dist
5. Legg til en midlertidig build environment variable:
   Key: VITE_API_BASE_URL
   Value: https://placeholder.invalid/api
6. Klikk Create Static Site.
7. Vent pa at status blir Live.
8. Kopier nettstedets offentlige adresse fra tjenestesiden. Den ser typisk slik ut:
   https://navn.onrender.com
   Kall denne adressen FRONTEND_URL videre i oppskriften.

Den midlertidige adresseverdien gjor bare at frontend kan bygges for backend
er klar. Den skal erstattes i del 3.4.

3.2 Opprett backend-tjenesten
1. I Render Dashboard, klikk + New og velg Web Service.
2. Velg samme GitHub-repo alannala911/SET18 og klikk Connect.
3. Fyll ut tjenestesiden:
   Name: for eksempel set18-backend
   Branch: main
   Root Directory: backend
   Runtime/Language: Node
   Build Command: npm install
   Start Command: npm start
   Instance Type: Free for en test, hvis Free er tilgjengelig
4. Finn Environment Variables pa opprettelsessiden. Legg inn hver variabel
   enkeltvis med Add Environment Variable:

   Key: NODE_ENV
   Value: production

   Key: MYSQL_URL
   Value: hele MySQL-tilkoblingsstrengen fra del 2.3

   Key: MYSQL_SSL
   Value: true

   Key: ADMIN_EMAIL
   Value: din administrator-e-post

   Key: ADMIN_PASSWORD
   Value: et nytt, unikt passord pa minst 12 tegn

   Key: CORS_ORIGINS
   Value: FRONTEND_URL, for eksempel https://navn.onrender.com

   Key: PUBLIC_FRONTEND_URL
   Value: samme FRONTEND_URL

   VIKTIG: Render kan bruke MYSQL_URL som hemmelig miljovariabel. Ikke vis,
   kopier til et offentlig sted eller lagre denne verdien i Git.
5. Klikk Deploy Web Service.
6. Kopier backendens offentlige adresse nar tjenesten er opprettet, for eksempel:
   https://set18-backend.onrender.com
   Kall denne BACKEND_URL videre.

Hvis den forste deployen feiler fordi databaseleverandorens nettverksregel
ennå ikke tillater Render, fullfor del 3.3 og deploy backend pa nytt.

3.3 Tillat bare backendens forbindelser til databasen
1. I Render Dashboard, aapne backend-tjenesten.
2. Klikk Connect oppe til hoyre.
3. Velg fanen Outbound.
4. Kopier IP-intervallene som vises for tjenestens region. Render kan vise
   flere intervaller; noter alle.
5. Aapne databaseleverandorens nettverksinnstillinger for database/klynge.
6. Aktiver endepunktet som backend skal bruke, hvis det kreves.
7. Fjern eventuell regel som gir tilgang fra alle IP-adresser.
8. Legg til backendens utgaende IP-adresser/intervaller i allowlist/firewall
   etter leverandorens skjema. Hvis du valgte privat nettverk, folg i stedet
   leverandorens private networking-oppskrift.
9. Lagre nettverksendringene.
10. Gaa tilbake til Render-backend og velg Manual Deploy > Deploy latest commit
    (eller tilsvarende deploy-knapp).
11. Vent til deploy-status er Live.

IKKE bruk en funksjon som "Add Current IP" for a gi tilgang til Render; den
gir normalt tilgang til din PC, ikke backend-tjenesten. Ikke bruk Allow all
for normal drift. Hvis hostingplanen ikke gir statiske egress-IP-er, avklar
privat tilkobling, faste IP-er eller annen stottet nettverkslosning med
hostingleverandoren. Ikke la databasen sta apen for alle som en snarvei.

3.4 Koble frontend til backend
1. I Render Dashboard, aapne den statiske frontend-tjenesten.
2. Klikk Environment i menyen til venstre.
3. Finn VITE_API_BASE_URL og endre verdien til:
   BACKEND_URL/api
   Eksempel: https://set18-backend.onrender.com/api
4. Velg Save, rebuild, and deploy. Det er viktig a bygge pa nytt fordi
   VITE_API_BASE_URL leses nar frontend bygges.
5. Vent til frontend-tjenesten igjen viser Live.

DEL 4 - KONTROLLER AT ALT VIRKER
--------------------------------

1. Aapne denne adressen i en nettleser, med din faktiske BACKEND_URL:
   BACKEND_URL/api/health
2. Riktig produksjonssvar skal inneholde:
   "status":"ok"
   "storage":"mysql"
3. Hvis serveren ikke starter:
   - Aapne backend-tjenestens Logs i Render.
   - Se etter feil om MYSQL_URL, databasepassord, TLS, IP/firewall-regel,
     manglende databasetilgang eller ugyldige HTTPS/CORS-adresser.
   - Kontroller at MYSQL_URL er pa backend-tjenesten, ikke frontend.
   - Kontroller at databasebrukeren har lov til a opprette tabeller ved
     forste oppstart. Alternativt ma en databaseadministrator opprette
     tabellene.
   - Rett miljovariabelen eller IP-regelen, lagre og deploy pa nytt.
4. Aapne FRONTEND_URL. Test medlemsregistrering og opprettelse av en aktivitet.
5. Aapne FRONTEND_URL fra en annen mobil/datamaskin. Kontroller at samme
   aktivitet og data er synlige. Administratorinnlogging krever fortsatt
   administratorens e-post og passord.
6. Logg inn som administrator og aapne Min side. Administratorer kan opprette
   eller fjerne andre administratorer. Hovedadministrator kan ikke fjernes.

HVA BACKENDEN LAGRER OG FLYTTER
------------------------------
- Medlemskap, søknader, aktiviteter, bestillinger, innstillinger og
  revisjonslogg lagres i MySQL nar MYSQL_URL er satt.
- Backend oppretter tabellene set18_application_state og set18_uploads ved
  oppstart.
- Databasebrukeren trenger tillatelse til a opprette og lese/skrive tabellene.
- Etter forste oppstart er MySQL kilden til sannhet.
- Hvis MySQL-tabellen er tom ved forste oppstart, backend kan seed-e den fra
  backend/data/application-store.json hvis den filen finnes pa serveren.
  Filen ligger vanligvis ikke i GitHub fordi datafiler er ignorert. Lokale
  data fra din PC flyttes derfor ikke automatisk til Render.
- Eksisterende lokale aktivitetsbilder og medlemsvedlegg flyttes heller ikke
  automatisk. Nye opplastinger lagres i MySQL.
- Ikke slett database-raden for a prove en ny import etter produksjonsstart.
  Det kan overskrive/fjerne applikasjonstilstanden.
- Kontroller backup og gjenoppretting for ekte bruk. Velg databehandling og
  lagringsregion med hensyn til personvern, særlig medlemsopplysninger og
  opplysninger om mindrearige.
- Gratis Render backend kan sove etter inaktivitet og bruke tid pa a starte.
  Gratis database- og hostplaner har kvoter, vilkar og kapasitetsgrenser.
  De er ikke ubegrenset og bor ikke regnes som produksjonsgaranti.

NYTTIGE LEVERANDORVEILEDNINGER
------------------------------
Databaseleverandoren er ikke valgt, sa det finnes ingen leverandorspesifikk
lenke eller knappesti her ennå. Nar leverandor er valgt, bruk dens offisielle
instruksjoner for:
- opprette administrert MySQL/MySQL-kompatibel database
- opprette databasebruker og hente connection string
- TLS/SSL-konfigurasjon for Node.js/mysql2
- private nettverk eller IP-allowlist
- sikkerhetskopiering og gjenoppretting

For denne backendens aksepterte tilkoblingsformat, se avsnittet "Use a hosted
MySQL database" i backend/README.md. Backend forventer MYSQL_URL med mysql://
og valgfri MYSQL_SSL=true; en leverandors dokumenterte driverinnstillinger ma
vaere kompatible med dette.
